# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные 
Товар:
`interface IProduct` {
  `id: string;` Уникальный идентификатор продукта
  `description: string;` Краткое описание товара
  `image: string;` Ссылка на изображение товара
  `title: string;` Название товара
  `category: string;` Категория, к которой относится товар
  `price: number;` Цена товара
} - интерфейс выступает шаблоном для описания структуры карточки товара 


Покупатель:
`interface IBuyer` {
  `payment: TPayment;`  Способ оплаты, выбранный покупателем
  `email: string;` Электронная почта покупателя
  `phone: string;` Контактный телефон покупателя
  `address: string;` Адрес доставки заказа
} - интерфейс выступает шаблоном для описания структуры покупателя

### Модели данных

Каталог товаров:

  Класс: Catalog

  Данные:
    хранит массив всех товаров `_products:IProduct[] | undefined`
    хранит товар, выбранный для подробного отображения `_selectProduct:IProduct | undefined`
  
  Методы:    
    сохранение массива товаров полученного в параметрах метода`set products(val: IProduct[])`
    получение массива товаров из модели `get products():IProduct[]`
    получение одного товара по его id `findProductById(id: string): IProduct | undefined`
    сохранение товара для подробного отображения `set selectProduct(val:IProduct)`
    получение товара для подробного отображения `get selectProduct():IProduct | undefined`

Корзина:

  Класс: `Basket`

  Данные:
    хранит массив товаров, выбранных покупателем для покупки `_selectedProducts:CartItem[]`
  
  Методы:
    получение массива товаров, которые находятся в корзине: `get selectedProducts():IProduct[]`
    добавление товара, который был получен в параметре, в массив корзины `add(val:IProduct)`
    удаление товара, полученного в параметре из массива корзины `remove(val:IProduct)`
    очистка корзины `clear()`
    получение стоимости всех товаров в корзине `totalCost():number`
    получение количества товаров в корзине `totalCount():number`
    проверка наличия товара в корзине по его id, полученного в параметр метода `inBasket(id:string):boolean`

Покупатель:

  Класс: `Buyer`

  Данные:
    информация о пользователе `_buyerInfo:IBuyer | undefined`

  Методы:
    сохранение данных в модели `set info(val:IBuyer)`
    получение всех данных покупателя `get info():IBuyer | undefined`
    очистка данных покупателя `clear()`
    валидация данных `validate()`

### Слой коммуникации

Класс: `WebLarekApi`

Назначение: 
  Прослойка между бизнес-логикой приложения и внешним API. Отвечает за получение и отдачу данных из внутренних моделей в формат API и обратно.

Методы:
  Получение каталога `getProducts`  
  Оформление заказаз `postOrder`.

### Слой представления 

Класс `Card`
Абстрактный базовый класс для всех карточек товара.

Конструктор:
  принимает корневой DOM-элемент карточки:`constructor(container: HTMLElement)`

Поля класса:
  заголовок карточки: `titleElement: HTMLElement` 
  цена карточки: `priceElement: HTMLElement`

Сеттеры:
  устанавливает название товара: `set title(value: string)`
  устанавливает цену, при null выводит «Недоступно»: `set price(value: number | null)`

Класс `CardGallery`
Карточка товара в каталоге. Наследуется от Card.

Конструктор:
  принимает корневой DOM-элемент и объект с обработчиками: `constructor(container: HTMLElement, actions?: IGalleryCardActions)`

Поля класса:
  изображение товара: `imageElement: HTMLImageElement` 
  категория товара: `categoryElement: HTMLElement`

Сеттеры:
  устанавливает изображение: `set image(value: string)`
  устанавливает категорию: `set category(value: string)`

События:
  При клике по карточке вызывается обработчик `actions.onClick`

Класс `CardPreview`
Детальная карточка товара, отображается в модальном окне 
Наследуется от `Card`

Конструктор:
  принимает корневой DOM-элемент и объект с обработчиками: `constructor(container: HTMLElement, actions?: ICardPreviewActions)`

Поля класса:
  изображение товара: `imageElement: HTMLImageElement`
  категория товара: `categoryElement: HTMLElement`
  описание товара: `descriptionElement: HTMLElement`
  кнопка действия: `buttonElement: HTMLButtonElement`

Сеттеры:
  устанавливает изображение: `set image(value: string)`
  устанавливает категорию: `set category(value: string)` 
  устанавливает описание: `set description(value: string)`
  устанавливает текст кнопки: `set buttonText(value: string)` 
  блокирует/разблокирует кнопку: `set buttonDisabled(value: boolean)`

События:
  При клике по кнопке вызывается обработчик `actions.onClick`

Класс `Gallery`
Контейнер для отображения карточек каталога.

Конструктор:
  принимает корневой DOM-элемент галереи: `constructor(container: HTMLElement)`

Сеттеры:
  заменяет содержимое галереи массивом карточек: `set items(items: HTMLElement[])`

Класс `Header`
Шапка сайта с логотипом и кнопкой корзины.

Конструктор:
  принимает корневой DOM-элемент и брокер событий: `constructor(container: HTMLElement, event: IEvents)` 

Поля класса:
  кнопка открытия корзины: `buttonElement: HTMLButtonElement`
  счётчик товаров в корзине: `counterElement: HTMLElement`

Сеттеры:
  устанавливает количество товаров: `set counter(value: number)`

События:
  При клике по кнопке корзины генерируется событие `basket:open`

Класс `Modal`
Универсальное модальное окно.

Конструктор:
  принимает корневой DOM-элемент модального окна: `constructor(container: HTMLElement)`

Поля класса:
  кнопка закрытия: `closeButtonElement: HTMLButtonElement`
  контейнер для содержимого: `contentElement: HTMLElement`
  внутреннее окно модалки: `windowElement: HTMLElement`

Методы:
  открывает модальное окно: `open(): void`
  закрывает модальное окно и очищает содержимое: `close(): void`
  рендерит содержимое и открывает окно : `render(data: IModalData): HTMLElement`

События:
  Модальное окно закрывается при клике по кнопке закрытия или по области вне окна

Класс `Basket`
Отображение корзины покупателя.

Конструктор:
  принимает корневой DOM-элемент и брокер событий: `constructor(container: HTMLElement, events: IEvents)`

Поля класса:
  список товаров: `listElement: HTMLElement`
  общая стоимость: `totalElement: HTMLElement`
  кнопка оформления: `buttonElement: HTMLButtonElement`

Сеттеры:
  устанавливает список товаров; при пустом массиве выводит «Корзина пуста»: `set items(items: HTMLElement[])`
  устанавливает общую стоимость: `set total(value: number)`
  блокирует/разблокирует кнопку оформления: `set disabled(value: boolean)`

События:
  При клике по кнопке «Оформить» генерируется событие `order:open`

Класс `BasketItem`
Строка товара в корзине.

Конструктор:
  принимает корневой DOM-элемент и объект с обработчиками: `constructor(container: HTMLElement, actions?: IBasketItemActions)`

Поля класса:
  порядковый номер товара: `indexElement: HTMLElement`
  название товара: `titleElement: HTMLElement`
  цена товара: `priceElement: HTMLElement`
  кнопка удаления: `deleteButton: HTMLButtonElement`

Сеттеры:
  устанавливает порядковый номер: `set index(value: number)`
  устанавливает название: `set title(value: string)`
  устанавливает цену: `set price(value: number)`

События:
  При клике по кнопке удаления вызывается обработчик `actions.onDelete`

Класс `Form`
Абстрактный базовый класс для форм оформления заказа. Содержит общий каркас, используемый OrderForm и ContactsForm: кнопку отправки, блок ошибок и подписку на событие submit.

Конструктор:
  принимает корневой DOM-элемент, брокер событий и функцию-обработчик отправки: `constructor(container: HTMLElement, events: IEvents, onSubmit: () => void)`

Поля класса:
  кнопка отправки формы: `submitButton: HTMLButtonElement`
  блок сообщений об ошибках: `errorElement: HTMLElement`
  функция-обработчик отправки: `onSubmit: () => void`

Сеттеры:
  блокирует/разблокирует кнопку отправки: `set valid(value: boolean)`
  выводит сообщение об ошибке: `set errors(value: string)`

События:
  При отправке формы вызывается переданный в конструктор обработчик `onSubmit`

Класс `OrderForm`
Первая форма оформления заказа: выбор способа оплаты и ввод адреса доставки. Наследуется от Form.

Конструктор:
  принимает корневой DOM-элемент и брокер событий: constructor(container: HTMLElement, events: IEvents)

Поля класса:
  кнопка оплаты онлайн: `cardButton: HTMLButtonElement`
  кнопка оплаты при получении: `cashButton: HTMLButtonElement`
  поле ввода адреса: `addressInput: HTMLInputElement`

Сеттеры:
  выделяет выбранный способ оплаты: `set payment(value: Payment)`
  устанавливает адрес доставки: `set address(value: string)`

События:
  При выборе способа оплаты генерируется событие `order:payment`
  При вводе адреса доставки генерируется событие `order:address`
  При отправке формы генерируется событие `order:next`

Класс `ContactsForm`
Вторая форма оформления заказа: ввод email и телефона покупателя. Наследуется от `Form`

Конструктор:
  принимает корневой DOM-элемент и брокер событий: `constructor(container: HTMLElement, events: IEvents)`

Поля класса:
  поле ввода email: `emailInput: HTMLInputElement`
  поле ввода телефона: `phoneInput: HTMLInputElement`

Сеттеры:
  устанавливает email: `set email(value: string)`
  устанавливает телефон: `set phone(value: string)`

События:
  При вводе email генерируется событие `contacts:email`
  При вводе телефона генерируется событие `contacts:phone`
  При отправке формы генерируется событие `contacts:submit`

Класс `Success`
Экран успешного оформления заказа.

Конструктор:
  принимает корневой DOM-элемент и брокер событий: `constructor(container: HTMLElement, events: IEvents)`

Поля класса:
  описание списанной суммы: `totalElement: HTMLElement`
  кнопка закрытия: `closeButton: HTMLButtonElement`

Сеттеры:
  устанавливает текст о списанной сумме: `set total(value: number)`

События:
  При клике по кнопке закрытия генерируется событие `success:close`

Класс Presenter
Содержит основную логику приложения и связывает модели данных с компонентами представления.

Конструктор:
  принимает брокер событий и экземпляр API: `constructor(events: EventEmitter, api: WebLarekApi)`

Поля класса:
модель каталога товаров: `catalog: Catalog`
модель корзины: `basket: Basket`
модель покупателя: `buyer: Buyer`
компонент шапки: `header: Header`
компонент галереи: `gallery: Gallery`
компонент модального окна: `modal: Modal`
компонент корзины: `basketView: BasketView`
компонент первой формы оформления: `orderForm: OrderForm`
компонент второй формы оформления: `contactsForm: ContactsForm`
компонент экрана успеха: `success: Success`

Методы:
подписывает презентер на все события приложения: `subscribe(): void`
загружает каталог товаров через API и передаёт его в модель: `loadProducts(): Promise<void>`
формирует карточки каталога на основе данных модели: `renderGallery(): void`
открывает модальное окно с детальной карточкой товара: `openPreview(): void`
добавляет или удаляет товар из корзины и закрывает модальное окно: `toggleProductInBasket(): void`
открывает модальное окно корзины: `openBasket(): void`
формирует список товаров корзины, общую стоимость и состояние кнопки оформления: `renderBasket(): void`
открывает первую форму оформления заказа: `openOrderForm(): void`
обновляет состояние первой формы оформления: `renderOrderForm(): void`
открывает вторую форму оформления заказа: `openContactsForm(): void`
обновляет состояние второй формы оформления: `renderContactsForm(): void`
отправляет заказ на сервер, очищает корзину и данные покупателя, открывает экран успеха: `submitOrder(): Promise<void>`
обновляет счётчик товаров в шапке: `updateHeaderCounter(): void`
использует данные из data в случае отсуствия подключения к api: `loadProducts():void`

События:
При открытии корзины обрабатывается событие `basket:open`
При изменении массива товаров каталога обрабатывается событие `catalog:changed`
При выборе товара в каталоге обрабатывается событие `product:select`
При выборе товара для подробного отображения обрабатывается событие `product:selected`
При добавлении/удалении товара из корзины обрабатывается событие `product:toggle`
При изменении корзины обрабатывается событие `basket:changed`
При удалении товара из корзины обрабатывается событие `basket:remove`
При открытии формы оформления обрабатывается событие `order:open`
При выборе способа оплаты обрабатывается событие `order:payment`
При изменении адреса доставки обрабатывается событие `order:address`
При изменении данных покупателя обрабатывается событие `buyer:changed`
При переходе ко второй форме оформления обрабатывается событие `order:next`
При вводе email обрабатывается событие `contacts:email`
При вводе телефона обрабатывается событие `contacts:phone`
При отправке формы оформления обрабатывается событие `contacts:submit`
При закрытии экрана успешного оформления обрабатывается событие `success:close`

### Описание архитектурного паттерна MVP

Проект построен на паттерне MVP (Model — View — Presenter). 
Этот паттерн разделяет приложение на три слоя, каждый из которых отвечает за свою зону ответственности. 
Такое разделение упрощает поддержку и развитие проекта: изменение интерфейса не затрагивает логику, а изменение логики — не затрагивает разметку.

Связь между слоями осуществляется через брокер событий (EventEmitter), что обеспечивает слабую связанность: ни Model, ни View не знают друг о друге напрямую, а Presenter не хранит ссылок на конкретные DOM-элементы.

#### Слой Model

Слой `Model` это данные приложения. Модели хранят состояние и содержат только ту логику, которая относится к обработке этих данных. Они ничего не знают о DOM и о том, как их данные отображаются.

В проекте три модели:

`Catalog` хранит массив всех товаров и товар, выбранный для подробного отображения. Умеет находить товар по id и сообщать об изменениях через событие catalog:changed.

`Basket` хранит массив товаров, добавленных покупателем. Умеет добавлять, удалять, очищать корзину, считать общую стоимость и количество товаров. Сообщает об изменениях через basket:changed.

`Buyer` хранит данные покупателя (способ оплаты, адрес, email, телефон) и валидирует их. Сообщает об изменениях через buyer:changed.

Все модели получают экземпляр EventEmitter через конструктор и используют его для генерации событий при изменении данных.

#### Слой View

Слой `View` это представление. Компоненты `View` отвечают исключительно за отображение данных и передачу пользовательских действий в виде событий. Каждый компонент получает корневой DOM-элемент через конструктор и не имеет прямого доступа к другим компонентам.

Базовый класс `Component<T>` предоставляет общий каркас для всех компонентов `View`:

хранит корневой элемент `container`;

предоставляет метод `render(data)` для обновления вида;

предоставляет утилиту `setImage` для работы с изображениями.

В проекте `View` представлен компонентами:

`Header` — шапка с логотипом и счётчиком корзины;

`Gallery` — контейнер для карточек товаров;

`Card (абстрактный)`, `CardGallery`, `CardPreview` — карточки товара: в каталоге, в детальном просмотре;

`Modal` — универсальное модальное окно;

`Basket` и `BasketItem` — корзина и её строки;

`OrderForm` и `ContactsForm` — две формы оформления заказа;

`Success` — экран успешного оформления.

Каждый компонент `View` подписывается на события от DOM-элементов (клик, ввод) и генерирует собственные события через `EventEmitter`. Он не хранит бизнес-логику и не знает, что происходит дальше с этими событиями.

#### Presenter

`Presenter` это центральная составляющая приложения. Он связывает между собой Model и View через EventEmitter. 

`Presenter`:

Создаёт экземпляры всех моделей и всех компонентов `View`.

Подписывается на события от моделей и от компонентов `View`.

Реагирует на эти события, вызывая методы моделей или обновляя представления.

Не содержит ссылок на DOM, а работает исключительно через публичные интерфейсы моделей и представлений.

Содержит всю бизнес-логику приложения: когда открыть корзину, когда отправить заказ, какие данные очистить после успеха.

В проекте Presenter реализован классом `Presenter`, который создаётся в точке входа `main.ts` и получает через конструктор брокер событий и экземпляр API-клиента.

Взаимодействие между слоями
Обмен данными между слоями полностью событийно-ориентированный. Схема выглядит так:

Пользователь взаимодействует с `View` → компонент генерирует событие через `EventEmitter`.

`Presenter` ловит событие → вызывает нужный метод модели.

Модель изменяет данные → генерирует событие об изменении.

`Presenter` ловит событие модели → обновляет соответствующий компонент `View` через сеттеры.

Такая схема полностью исключает прямые ссылки между `View` и `Model` и делает код расширяемым: чтобы добавить новое поведение, достаточно добавить обработку события в `Presenter`.

Преимущества выбранного подхода

Разделение ответственности. Каждый класс занимается одним делом: `View` отображением, `Model` хранением, Presenter `координацией`, `EventEmitter` передающий.

Слабая связанность. Компоненты общаются через события, а не через прямые вызовы друг друга.

Переиспользуемость. Компоненты View не зависят от бизнес-логики и могут использоваться в других местах проекта.

Тестируемость. Модели и Presenter можно тестировать изолированно от DOM.

Расширяемость. Логика сосредоточена в `Presenter`, а не размазана по компонентам.
